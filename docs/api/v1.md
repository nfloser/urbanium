# Versioned machine API

Urbanium exposes an application-independent HTTP API under /api/v1. The API is an outer application layer over existing city, capability, source and provider contracts; it does not move dashboard or HTTP framework behavior into the platform core.

## Run locally

From the repository root after installing the project:

    pip install -e ".[dev]"
    urbanium-api

The runtime uses cities/ by default. Override it with URBANIUM_CITIES. URBANIUM_HOST defaults to 127.0.0.1 and URBANIUM_PORT defaults to 8000.

The generated OpenAPI document is available at /api/v1/openapi.json and interactive documentation at /api/v1/docs.

## Discovery

The v1 API currently provides:

- GET /api/v1/cities
- GET /api/v1/cities/{city_id}
- GET /api/v1/cities/{city_id}/capabilities
- GET /api/v1/cities/{city_id}/sources

Discovery returns the validated canonical city contracts. Lists are deterministic so clients do not depend on YAML insertion order.

## Canonical observation reads

Provider reads use:

GET /api/v1/cities/{city_id}/sources/{source_id}/observations/{capability_id}

The source is explicit in the URL so a future city may expose more than one verified source for the same capability without making selection ambiguous.

A read is attempted only when the city exists, the capability is configured, the source is declared for that capability, and a validated runtime provider binding exists for the city/source/capability tuple.

The response embeds the existing canonical ProviderResult, including normalized observations, freshness and typed provider errors.

## HTTP and health semantics

Static deployment support and runtime provider health remain separate:

- provider available -> HTTP 200;
- provider degraded -> HTTP 200 with availability=degraded and its typed error;
- provider unavailable -> HTTP 503 with the full typed ProviderResult preserved;
- declared but non-configured capability -> HTTP 409 with capability_not_configured;
- no composed runtime adapter -> HTTP 503 with provider_not_bound;
- unknown city/source/capability -> HTTP 404 with a stable machine-readable problem body.

No cached observation is substituted for an unavailable live provider in this API slice.

## Runtime composition

The generic app factory accepts any implementation of the city-independent ObservationProvider protocol. The current runtime composition wires implemented DWD air-temperature adapters discovered below each city's providers/ directory. Adding a new provider adapter does not require changing core contracts.

## Contract checks

Tests generate the OpenAPI schema from the application and assert the v1 version plus required paths and response classes. HTTP-level tests also cover discovery, canonical available/degraded/unavailable provider results, missing bindings and candidate capabilities.

Any incompatible API change should be introduced under a new API version rather than silently changing /api/v1.
